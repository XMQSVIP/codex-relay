# OAuth 账户、凭据导入与桌面复用

模型请求仍由官方 app-server 建立连接。桥仅在单独 RT 导入时向官方 OAuth 服务交换一次完整凭据，后续续期与 OpenAI 模型传输仍由原生后端负责。账户与本机配置实例共用 Key、分组、原子选路、并发、取消及统计。

桌面绑定和 AT-only 导入在核对令牌身份、收到原生 `chatgptAuthTokens` 登录确认后即可继续，不重复查询 `getAuthStatus`。完整原生登录仍由原生凭据读取确认，认证刷新回调与账户绑定检查保持生效。

## 使用方法

“账户与连接 → 添加账户”提供“使用本机 Codex”（默认）、“登录其他 ChatGPT 账户”和“导入凭据”。选择本机后自动检测安装和有效配置，显示提供方、连接方式与默认模型。确认名称、分组后点击“连接并启用”，全程不发送模型测试请求；支持 ChatGPT 登录、官方 API Key 和第三方提供方，包括名称为 `OpenAI` 的自定义提供方。多个本机实例共享本机配置与上游额度。

检测不创建账户。检测后配置或身份变化会更新摘要，需再次点击连接；创建成功但启用失败时保留原账户，重试不重复创建。尚无凭据、登录进程、接入路由或运行/排队操作的空账户，可在详情中选择“使用本机 Codex”，保留 ID、名称与分组。已有凭据的账户不会自动转换。

本机账户在账户详情中“重新检测并更新”或关闭“启用账户”。原有桌面 ChatGPT 绑定仍使用原绑定方式，在登录方式中的“本机 ChatGPT 绑定详情”管理。客户端接入页只负责地址和 API Key；同分组已有 Key 可继续使用。

在“账户管理”点击“添加账户”，在弹窗中填写名称。创建后进入账户详情，也可从账户列表打开已有账户。列表展示登录、实例运行、账户启用与并发状态，可按名称、邮箱、分组搜索。日常用“启用账户”控制是否提供服务，操作区提供测试对话、展开详情、账户设置和删除入口，手动启动、停止和重启统一位于详情“高级能力 → 实例维护”。详情分为“登录与凭据”“接入与调度”“高级能力”；先选择一种登录方式：

- 使用 ChatGPT 浏览器或设备码登录。官方后端在该账户的独立 CODEX_HOME 保存并维护登录。
- 导入官方 auth.json，或包含 access_token、id_token、refresh_token 的 JSON。兼容 camelCase 字段。完整凭据进入该实例的 home/auth.json，由原生后端续期。
- 导入单独 Codex Refresh Token：在“纯文本令牌类型”选择 Refresh Token 后粘贴，或导入 `{"refresh_token":"..."}` / `{"refreshToken":"..."}` JSON（也支持 `tokens` 包装）。桥使用官方 Codex client ID 向固定 `https://auth.openai.com/oauth/token` 交换一次；沿用连接设置中的自动、直连或自定义代理，禁止重定向与自动重试。返回有效 AT、ID Token 并通过身份校验后保存完整 auth.json；新 RT 优先保存，未返回新 RT 时保留导入值。缺少 ID Token、AT 已过期、身份不一致或服务拒绝时导入失败。只持有其他 OAuth 客户端的 RT 不在此入口支持范围。
- 若原生文件包含续期来源与登录标识，会在校验后保留；续期签发方仅接受官方 auth.openai.com。AT 和 ID Token 中明确提供的工作区或用户身份不一致时拒绝导入。
- 导入单独 Access Token（JWT）。账户 ID 从 token claims 提取，提供的 accountId 如不一致则拒绝。AT-only 保存在受限实例目录，通过 chatgptAuthTokens 注入新进程；连续文本对话复用进程时仍逐轮校验身份和有效期，相同令牌不重复登录，令牌更新时重新注入。到期必须重新导入。
- 桌面 ChatGPT 绑定。桥通过本机官方后端 getAuthStatus（includeToken=true、refreshToken=false）读取当前 AT（原生认证读取可能自动续期），在独立推理进程中使用外部令牌模式。绑定文件只保存身份与模式，不复制桌面的 RT，不调用桌面 logout。桌面原生认证接口不能提供令牌时，该操作明确失败。

登录或导入后，在账户列表或详情“接入与调度”中开启“启用账户”。首次启用会检查原生认证、读取配置和模型目录，并回收检查进程，随后自动启动一个待命实例，不发送模型请求。服务重启后会恢复已启用且已配置接入的账户实例；重复启用复用已有实例。HTTP Responses 与原生 WebSocket 使用同一账户配置。关闭后停止接收新请求，等待当前任务完成后自动停止实例，路由配置和凭据保留。恢复已配置账户无需重新检测；更换凭据仍会使旧路由失效。手动停止或重启会中断当前任务，需要确认，且不改变账户启用状态。客户端每次请求的 `model` 决定实际调用模型，仍受上游账户权限、Key 模型授权和扩展能力约束。

列表中的“账户设置”可进入详情页的“接入与调度”。“测试连接”是可选诊断，可以在接入启用或停用时运行。测试模型仅用于该次请求，不保存为账户模型，也不会启用、停用或替换现有路由。测试会发送一次真实模型请求并消耗用量；失败不会改变接入状态或账户的调度健康状态。

独立账户可在“登录与凭据 → 凭据管理”点击“导出凭据”，下载可直接重新导入的单账户 JSON。完整凭据保持原有续期模式，仅 AT 的凭据到期后仍需手动更新。需同时保存名称、分组和并发时，在列表勾选账户并“导出账户备份”，之后使用“导入账户备份”恢复。迁移后停用旧实例，避免同一 RT 被多个实例同时刷新。

管理 API：

- `POST /api/accounts/{id}/credentials`：`{"document":{...}}` 导入 JSON；也接受 `{"refreshToken":"..."}` 或原有 `{"accessToken":"..."}`。成功响应只包含保存与续期模式，不返回凭据。
- `POST /api/accounts/{id}/activation`：统一启用或停用账户，携带 revision 和 enabled；停用保留配置并在任务完成后停止实例。

- `POST /api/accounts/{id}/route`，`{revision, enabled:true}` 启用或刷新接入，`enabled:false` 停用；不再接受 `model` 字段。
- `POST /api/accounts/{id}/connection-test`，`{model?: "模型ID"}` 运行可选连接测试；省略模型时使用原生默认模型。成功返回 `{ok:true, model}`。不修改配置 revision。
- 凭据变化仍会使旧接入失效，重新登录或导入后需再次启用。

## 隔离与失效

- 每个账户有独立原生账户目录。配置与统计库不保存 token；导入凭据位于账户受限目录，不进入日志或管理响应。
- 桌面复用绑定工作区和可识别的用户身份。桌面切换用户或工作区后请求失败，须主动重新绑定；不静默更换请求所属账号。
- 外部令牌刷新回调只在后端内部处理，不交给客户端工具回调或 SSE。桌面复用通过原生认证读取当前 AT，原生后端可能自动续期；桌面没有新令牌时明确失败。
- 成功导入、更换登录、绑定或退出会使旧路由失效；已有执行或排队请求时拒绝导入。RT 交换期间独占账户，交换或校验失败保留原凭据与路由。配置仍使用 revision 冲突检查。网络错误可能发生在上游已经轮换 RT 之后，因此不会自动重试，必要时须重新登录获取完整凭据。
- “退出此实例 / 解除桌面绑定”只清除桥管理的账户文件。它不撤销 OpenAI 全局登录，也不让个人桌面退出。
- 多个实例如果使用同一上游账户，仍共享该账户的额度。导入同一 RT 到多个独立刷新者可能遇到令牌轮换冲突；复用本机桌面应使用原生绑定入口。

## 当前边界与验证

仅支持官方默认 OpenAI/Codex OAuth 提供方。不会从导入文件接受 base URL、浏览器 Cookie、MCP 配置或自定义认证头。API Key、PAT 不是本入口的 OAuth JSON 模式。RT-only 通过官方服务补全，不伪造缺失 token；AT+RT 但缺少 ID Token 的不完整文件仍拒绝导入，可改用单独 RT 导入。

新增媒体能力继续默认关闭，需在此账户的能力面板单独验证和启用。Responses 历史仍仅在内存保存一小时。

## 统一本机连接管理接口

- `POST /api/local-connection/inspect`：检测安装与配置，返回有效期 10 分钟的检测 ID，以及脱敏提供方、认证类型、默认模型和服务 origin；不返回令牌或账户身份指纹，不创建账户。
- `POST /api/local-connection/connect`：提交 `requestId`（UUID）、`inspectionId`、`name`、`groupId` 和 `revision`；可选 `accountId` 用于空账户转换或更新本机账户。重新检测一致后提交，返回 `enabled`、`pending` 或 `changed`。`pending` 包含已保存的账户与错误；`changed` 包含新的检测结果，需重新确认。
- 新建账户的请求 ID 持久化到账户元数据，重试使用相同 ID，即使服务重启也不会重复创建。服务重启后需重新检测，但可继续使用原请求 ID。浏览器同标签页保留未完成的请求 ID。
- `source` 用于区分账户来源；创建、登录、凭据和路由接口各自提供当前操作入口。通过统一本机连接创建的账户保存 `connectionRequestId`，用于重复提交时查找同一账户；该元数据不要求其他创建方式提供。

### 统一本机连接验收

先构建发布程序和前端、准备本机原生安装，再执行 `python scripts/test_local_connection.py`。脚本启动使用临时数据目录的发布服务，通过 HTTP 验证预览不创建账户、并发重复提交只创建一个账户、空账户转换保留身份，以及已有凭据不会被覆盖；最后检查推理请求数为零并关闭测试服务。它不修改现有账户数据，不调用模型。

原生端到端验收使用发布程序：未优化 Rust 测试进程中的大文件安装完整性校验在本机曾超过检测时限，不能替代发布版的 HTTP 验收。状态与失败恢复仍由 `node scripts/cargo-with-memory.mjs test --locked --lib local_connection` 的合成测试覆盖。
