# 请求链路与并发检查记录

日期：2026-10-28。目标场景：10 个独立原生账户，每账户 10 并发。

本记录覆盖接入校验、调度、认证、实例与会话、RPC/流式、取消与退出、存储统计和后台轮询的主要运行路径。它不是对全部代码无缺陷的保证，也不把本地模拟上游结果等同于真实服务的容量承诺。

## 运行路径保护

| 问题 | 处理 | 验证依据 |
| --- | --- | --- |
| 并发请求的额度监听器会接收并复制全部模型事件，同一额度通知还会重复写库 | 独立的额度事件通道，以共享事件和一次领取标记确保仅处理一次；模型事件不会进入额度通道 | 600 条文本事件不会唤醒额度监听器，多个订阅者仅领取一次通知的单元测试 |
| 空闲回收停止实例失败后仍清空槽位 | 保留实例所有权，标记退出并重试，保留后续停止/退出的清理入口 | 失败分支审阅；此分支尚未注入真实操作系统终止失败 |
| WebSocket steer 等待原生 RPC 时阻塞连接事件循环 | 独立 FIFO 控制队列，最多 8 条等待命令，按原始帧大小累计 64 MiB 预算，可取消；响应流继续转发 | 延迟 steer 时另一流继续输出、顺序保持、队列预算释放测试；预算不等同于 JSON 展开后的堆内存 |
| 重置卡状态轮询使用固定 interval，慢请求可重叠且关闭窗口后不取消网络请求 | 完成后再定时调度，卸载时 AbortController 取消 | 前端完整测试及构建 |
| 统计总页数可能超过 10,000，但接口拒绝该范围的页码 | 根据实际总页数截断请求页码，移除互相矛盾的固定上限 | 10,001 和 u32 最大页码均能安全截断的回归测试 |
| API Key 直连流式首响将 elapsed duration 写入 timestamp 字段，计算后可能被截为 0 | 写入实际首次增量时间戳，与原生链路的统计口径一致 | 模拟上游延迟后首响不得为零且不超过总耗时的测试 |
| 客户端用量汇总仍在调度锁中执行长查询 | 仅在锁内校验权限、读取活动数，历史汇总移到只读快照及受限后台任务 | cache_usage、gateway_evolution 等权限/用量回归 |
| 账户预热持有全局设置锁，拖慢其他账户操作 | 取得账户维护租约后释放全局锁；预热最多同时启动两个实例，并在启动前重新检查启用状态 | 账户启停测试；原生容量验收 |
| 用量排行窗口排序处理全部历史行以取最新名称 | 先聚合，再利用账户/密钥时间索引查最近非空名称 | 相同数据的新旧 SQL 结果对比、统计筛选/重命名/空值回归 |
| 不支持重置卡的提供方先校验兑换上下文，错误返回“路由已变化” | 在创建管理租约及兑换尝试前拒绝不支持的提供方 | 管理接口回归：返回 RESET_UNSUPPORTED，且无待确认兑换、无模型调用 |

## 检查范围与已确认的保护

- 接入：请求正文及解压后大小有上限；API 密钥按请求校验，WebSocket 持续校验授权；模型请求不因结果未知而自动重放。
- 调度：容量判断、占额、队列出队仍在同一临界区；等待者先注册通知，取消/超时/丢弃释放状态。
- 认证：认证结果按原生实例及绑定/凭据摘要缓存；失效或过期时重读，并发刷新合并；客户端授权与上游认证分别校验。
- 会话：历史匹配在账户锁外计算，领取时校验完整会话快照；不同密钥不共享续聊上下文；同一 Key 改分组后重新校验当前账户与模型授权，授权有效时可续用存活线程和工具回调。
- 生命周期：启用原生账户保留健康预热实例；资源预算、健康与配置变更检查仍生效，活动读租约覆盖准备及执行，轮换等待在途请求；停用不补建。
- 流式：模型、RPC、WebSocket 队列均有界，传输有超时和断开取消；工具回调按 thread 隔离；追加输入现在不会阻塞输出转发。
- 数据：WAL 只读快照与调度写入分离；自动历史清理分批执行；手动清空要求无执行/排队请求。
- 前端：主要轮询使用完成后调度并支持取消；本轮补齐遗漏的重置卡状态轮询。

## 容量及性能证据

- 原生容量：`scripts/test_account_concurrency.py --capacity` 使用隔离 CODEX_HOME、真实已安装 app-server、本地合成 HTTP 上游，验证了 10 账户各 10 活跃请求，合计 100 个同时请求，全部完成。
- 同一次运行还覆盖了同账户多用户、同密钥多会话、排队、续聊、单请求取消、工具调用和进程轮换；合计 149 次合成上游请求，真实模型调用为 0。
- 启动优化后再次运行 `--capacity --check-standby`，全部通过，并额外确认 125 秒空闲后复用预热进程、停用观察 35 秒不补建。
- SQL 微基准：Python SQLite，同一内存数据库 100,000 行、10 个账户、100 个密钥。账户排行约 401.49 → 91.02 ms，密钥排行约 390.29 → 148.52 ms，结果一致。仅为排行 SQL，不代表端到端模型首响收益；原始结果在 `.cache/grouped-usage-benchmark.json`。

## 验证边界

- 原生容量测试为短输出、受控本地上游；没有使用真实 ChatGPT 登录凭据验证服务端限流、真实网络首响或吞吐。
- 尚未进行多小时持续运行、100 个长上下文/图片请求同时执行的 RSS 峰值测量。
- 大时间范围的统计仍需要扫描匹配记录；深分页仍使用 OFFSET，其开销会随历史量增加。本轮消除了调度锁阻塞并降低排行排序开销，没有声称查询成本与记录数无关。
- 真实磁盘故障、进程树无法终止等操作系统级失败尚未全部故障注入，不能仅凭正常路径测试宣称这些场景已实测通过。

## 账户限流冷却

已补齐原生 Codex/ChatGPT 登录账户的短期限流冷却，API Key 账户及原生 API Key 配置排除。按账户和路由版本隔离，采用 30–300 秒退避及单请求恢复探测；合并并发限流观测，迟到成功不解除新冷却。原生长会话遇到限流及时结束并结算，当前失败请求不自动重放。策略与进程内状态的边界见 [运行说明](OPERATIONS.md)。

## 2026-10-29：调度与统计开销优化

- API Key 上游检测直接检查分组成员的路由类型，避免每次请求生成完整管理状态快照。账户暂停、删除中的路由仍由原准入路径校验。
- 等待者仍先检查取消、权限、存储状态和超时；自身容量受限时直接继续等待，不再遍历整个队列寻找首个可执行请求。可执行请求仍遵守原公平顺序，检查与占额保持在同一锁内。250 ms 定时复查及状态变化通知保留。
- 统计只生成实际使用的筛选条件，值使用绑定参数，让账户、密钥、分组筛选可使用已有时间索引。计数、用量和时延汇总合并为一次扫描，保持未知值、零值、推理范围和 WAL 快照口径；接口和数据库结构未变。
- 新增名称筛选回归，覆盖稀疏参数组合、含 SQL 字符的字面子串、空字符串及 NULL 名称。已有统计回归覆盖完整/部分用量、名称变更、时间边界、分页、排行和趋势的一致性。

使用 `node scripts/cargo-with-memory.mjs test --locked --test account_concurrency hundred_requests_with_large_history_and_concurrent_statistics -- --ignored --nocapture`，在同机默认 test 构建中对比 10 账户、100 并发、10 万历史行及连续 5 次统计：

| 指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 准入 P95 / P99 | 17.08 / 23.79 ms | 16.53 / 20.76 ms |
| 100 次准入与结算 | 135.07 ms | 134.37 ms |
| 统计耗时范围 | 1699–1748 ms | 1481–1565 ms |
| 平均统计耗时 | 1722 ms | 1507 ms |

统计平均耗时减少约 12.5%。这是一次修改前后对比，准入的微小差异不能视为稳定收益。该测试没有队列积压，也不调用模型；不能据此量化队列优化收益或真实模型首响提升。大范围统计仍扫描历史，深分页仍使用 OFFSET，尚未消除随数据量增长的开销。
