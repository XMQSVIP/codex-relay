# 账号管理

“本机 Codex”表示复用本机配置，不是一种登录模式。订阅列上方显示套餐，下方显示当前订阅周期到期日期；点击可查看完整时间、自动续费状态和手动刷新。日期按浏览器本地时区显示。API Key 和非 ChatGPT 提供方不查询订阅日期。

订阅元数据保存在本地 SQLite 中并绑定账户身份和提供方配置，不保存令牌。账户列表只读缓存；套餐类型利用已有认证和额度通知更新，不发送模型请求。首次启用后在后台查询当前提供方的 `/backend-api/subscriptions`，取得未来的 `active_until` 后，到期前不再自动查询；已有后台检查在到期后安排一次更新。失败、日期缺失或仍返回过去日期时，已有结果保留并标记“待确认”，24 小时后重试。停用账户暂停自动查询；手动刷新合并同账户请求，最短间隔 60 秒。服务重启后先核验身份，再复用未到期记录；退出、换绑、切换提供方和删除账户会清除相应记录。自动续费的日期只表示当前周期结束，不代表套餐必然失效。

首次成功读取订阅前，超时、连接中断、原生启动失败等临时错误会按 1、5、15 分钟的间隔自动补查，之后恢复 24 小时间隔；认证失败和不支持的账户不进行短间隔重试。重启保留补查进度，停用期间暂停；取得有效日期后不再提前补查。首次读取成功但日期缺失或已过期时仍按 24 小时间隔处理。订阅列显示“正在查询”或“稍后重试”，到期时间通过概览轮询自动更新，详情显示下一次重试时间，无需手动刷新。

订阅自动与手动查询均使用独立进程，可与推理并行，不等待账户空闲，也不占用推理并发槽。同账户查询串行、最短间隔 60 秒，查询并发上限 2；登录和凭据变更保持互斥，服务退出时不再准入新的订阅查询。查询成功、失败或任务取消均释放自身租约，不停止推理实例。

订阅 HTTP 查询限时 5 秒、响应上限 64 KiB，使用账户代理配置，不跟随重定向或跨站回退；原生进程准备和认证另有超时控制。管理接口为 `GET /api/accounts/{id}/subscription`（只读缓存）和 `POST /api/accounts/{id}/subscription/refresh`（手动刷新）。元数据读取失败不更改账户启用、额度状态或调度健康。

## ChatGPT 原生登录

可通过“复制授权链接”让账户持有人在另一台电脑上完成授权，再由管理员在同一次登录会话中提交对方返回的完整回调地址。无需提供密码；十分钟内保持中转站运行，不要重新生成链接。完成后接入的是该持有人授权的账户。

“使用 ChatGPT 登录”和“使用设备码登录”都由中转站为该账户启动的独立 Codex app-server 处理，不会登录或退出正在使用的桌面窗口。开始前会检查冲突；开始后暂停此账户接入。登录成功也不会自动恢复路由，请到“接入与调度”确认并启用。

浏览器授权后，管理页每两秒查询本次登录结果。成功必须同时满足原生完成通知、账户可读和独立目录凭据校验；已有旧凭据不代表本次登录成功。取消、失败、超时和进程退出均明确显示。会话最长十分钟，终态保留三十分钟；刷新管理页可以恢复查看，重启中转站后需重新发起。

远程浏览器授权后若跳转到本地回调地址且无法打开，可展开“已授权但没有反应？”，粘贴地址栏完整的 `http://127.0.0.1:1455/auth/callback?...` 地址。中转站校验其所属会话后转交给服务器上的原生监听，再等待原生结果。只能使用本次授权返回的实际地址，不能只粘贴授权码。提交后不要重复提交；转交不确定时仍会等待原生结果，到期后重新发起。

手动回填要求原生登录进程仍在运行，不能修复监听启动失败。端口 1455 被占用时不会取消其他应用的登录，请完成其他登录后重试或使用设备码。同一中转站同时只允许一个浏览器登录；不同账户可分别使用设备码。登录期间不能启用接入、导入凭据或修改会重启进程的配置；停止、退出或删除账户会先结束登录。

失败或取消后不自动恢复原路由，不删除残留的旧 `auth.json`。回调地址包含一次性授权参数，请勿粘贴到聊天或日志；页面仅在内存中使用，服务不会将其记录到请求历史。

## API Key 账户

“添加账户 → API Key”可填写账户名称、基础 URL、上游密钥及传输方式。基础 URL 是完整 API 前缀，例如 `https://example.com/custom/v1`；中转站只追加 `responses`、`models` 或图片接口路径，不自动添加 `/v1`。

导入后账户默认停用。在“接入与调度”手动启用后，可与同组 ChatGPT 账户共用调度、队列、并发及统计。此类账户直接连接上游，无需本机 Codex 或 app-server，也不读取 ChatGPT 订阅、周期额度或重置卡。上游不提供 `/models` 时仍可使用客户端指定的模型。

“上游配置”支持修改地址、传输方式及密钥；已配置密钥时留空表示保留。保存配置不发送模型请求；只有实际变化才更新路由并要求账户没有执行或排队请求，相同配置保存不改变 revision、绑定或连接。上游身份变化后旧响应 ID 和加密条目绑定失效，需新建会话；完整普通文字历史可正常回放。密钥存放在受保护的账户目录内，普通管理响应不回显密钥，显式导出的账户备份包含密钥；不要分享整个运行数据目录。

默认 HTTP/SSE；“WS 优先”用于兼容的 Responses 生成请求。只有在发送生成请求前、上游明确不支持 WebSocket 握手时才回退 HTTP。认证失败、限流或发送后断线不会重放请求。连接测试须填写上游模型 ID，会消耗实际用量。图片、模型列表、compact 及响应查询/删除使用 HTTP。

API Key 直连保留 `context_management` 等请求参数，由上游决定支持和执行；不会经过原生 RPC 的参数忽略逻辑。需要该语义的客户端应使用仅含相应 API Key 账户的分组，避免混合分组首次请求被分配给原生账户。自动压缩、续聊及 ChatGPT/OAuth 直连的边界见[context_management 与直接转发](RESPONSES.md#context_management-与直接转发)。

管理接口：`POST /api/accounts` 接受 `{ "name": "上游", "source": "api-key", "upstream": { "baseUrl": "https://example.com/v1", "apiKey": "上游密钥", "transport": "http-sse" } }`；`POST /api/accounts/{id}/upstream` 接受 `{ "revision": 1, "baseUrl": "https://example.com/v1", "transport": "ws-first" }`，可选 `apiKey` 用于替换密钥。管理接口仍受本机管理会话保护。

账号页提供账号池状态、分组筛选、今日推理用量、上游额度和批量维护。账户列表、详情和批量配置支持多选所属分组；列表搜索和分组筛选匹配任一所属分组。账户至少保留一个分组，各组共享该账户的并发上限。配置、运行状态、调度健康与额度阻塞相互独立；并发已满不是账号故障，自动额度避让不会修改管理员启用开关。

列表和详情提交账户开关后立即显示“启用中…”或“停用中…”，等待期间禁止重复提交；成功后刷新服务端状态，失败保留原开关值并显示浮动错误提示。关闭后不接收新请求，当前任务完成后停止实例；需要立即中断时使用实例维护操作。

列表主行的“周期用量”显示最长有效额度窗口内已用的总 Token（有周窗口时使用周窗口），同时显示上游使用率与各窗口进度条。鼠标悬浮、键盘聚焦或点击后显示各窗口的使用率、Token 消耗和重置时间；重叠窗口不相加，短周期/长周期按实际时长显示。未知、部分用量、读取失败和过期数据明确标记。有效窗口剩余额度低于 10% 时，对应的百分比与进度条显示橙色；额度耗尽显示红色，不额外添加提示文案。刚好剩余 10% 保持正常颜色，未知或已结束窗口使用中性色。

窗口 Token 按当前账号在本站保留的推理记录统计，范围为重置时间减去窗口时长至当前时间，以请求开始时间归属窗口。输入与输出相加，缓存不重复累加；没有请求时为 0，有请求但未报告完整用量时为未知或部分统计。缺少边界、窗口已结束或无法映射的额度桶不推算用量；这些本地 Token 不代表其他客户端的消耗，也不用于推算上游使用率。

“接入与调度”采用自适应的统一设置网格，代理、时区、启用和调度各自按标题、表单、说明与操作区排列。宽屏使用等宽分区，窄屏上下排列；内容沿工作区边缘对齐，不设置固定居中宽度。连接测试与检测分流说明默认折叠，展开后保留编辑内容。

账户启停、调度保存、凭据操作、额度刷新和删除等主动操作通过顶部浮动提示反馈结果，不改变列表或表单布局；提示支持关闭，并在操作弹窗关闭或账户行移除后继续显示。字段校验、登录授权步骤、检测结果与额度状态仍保留在相应区域。统一交互规则见 [管理界面与验证](UI-CONSOLE.md#操作提示)。

## 状态与用量

账号列表排除桌面调试连接；手动停用与分组暂停单独筛选，不计入待处理。筛选、分页和展开账号保存在 URL，返回账户列表时恢复。用量默认采用浏览器本地今天，日期边界兼容夏令时；服务端聚合全部推理记录，最近使用取保留历史中的最后一次推理。

`GET /api/accounts/metrics?from=<毫秒>&to=<毫秒>&accountId=<可选 UUID>` 返回 `accounts` 摘要和可选单账号 `models` 聚合，以及 `updatedAt`。只统计 `kind=inference`，成功率为成功÷成功与失败；缺失 Token 不作零值，缓存不重复累加。未设置 accountId 时不加载模型详情。

状态沿用概览轮询，用量每 30 秒刷新；行展开按需加载，失败保留旧值。历史仍沿用现有 30 天保留和清空规则。

“刷新账号数据”并行重新读取账号状态与今日用量，等待两者完成后提示结果；刷新期间不可重复提交。此操作只读取服务已有数据，上游额度和订阅需在对应详情中手动刷新。

## 临时测试对话

账户列表的对话图标和账户详情中的“测试对话”打开临时窗口，默认填入 `ciallo`，推理强度默认选择 `low`，点击发送才发起请求。支持选择或输入模型、选择推理强度、流式文本、多轮续聊、停止生成和清空。“糖果题”和“牛奶题”快捷按钮会立即发送完整预设题目，使用当前模型和推理强度；生成中禁用快捷按钮与强度选择。显示实际模型、首响、总耗时与已知 Token；未返回的统计显示“—”。关闭或按 Esc 取消当前请求并清空窗口内容，不显示用量消耗提示。

`POST /api/accounts/{id}/chat-test` 仅允许管理员调用，输入为可选 `model`、`reasoningEffort` 和交替的 `messages: [{role, content}]`，最后一条必须为 user。`reasoningEffort` 可为 `none/minimal/low/medium/high/xhigh/max/ultra`，省略或 null 时不向上游指定推理强度；原生与 API Key 账户均传递所选值。固定使用路径指定账户及其代理，不重试其他账户，不启用或修改路由；遵守维护互斥与并发限制。最多 16 轮、单条 32 KiB、总文本 48 KiB，沿用管理 API 的 64 KiB 请求体限制。回复最多 1 MiB，执行超时五分钟。SSE 发送 ready/delta/done/error，成功终态在执行清理和统计结算后发送。失败或停止的轮次仅用于窗口展示，不加入后续历史；切换模型前清空对话。测试模型下拉框展示账户完整目录并保留手动输入模型 ID 的入口；默认发送内容为 `ciallo`，清空对话后恢复这句。

对话内容仅保留在浏览器及当前请求内存，不写入响应存储、粘性缓存或失败正文。请求记录仅保存 `chat_test` 标记及账户、状态、耗时、用量等元数据。原生账户使用独立临时实例、ephemeral 线程，关闭原生历史和提示词遥测，日志放在清理后删除的临时目录；API Key 账户使用独立上游连接、完整内存历史与 `store:false`，不保存响应绑定。此约定是本程序的存储行为，上游服务的数据处理仍由其自身控制。

## 上游额度

`GET /api/accounts/{id}/quota` 读取缓存额度并聚合本地窗口用量；`POST /api/accounts/{id}/quota/refresh` 显式读取原生额度。快照状态为 `unknown/supported/unsupported/error`，返回窗口时长、使用百分比、重置时间（统一毫秒）、采集/尝试时间、过期与阻塞标记，不返回身份指纹或凭据。每个窗口附带可空的 `usage`（`from/to/requestCount/usageKnownRequests/totalTokens`）；概览中的额度使用相同结构。

通过原生 `account/rateLimits/read` 和 `account/rateLimits/updated` 读取；无模型探测请求。账号启用后采集一次，服务每 30 秒检查是否需要补读：近期使用的账号每 5 分钟补读，连续 30 分钟没有模型请求活动的账号每 15 分钟补读。闲置从最后一次模型请求结束时计时，执行中或排队中的模型请求仍算活动；没有模型请求记录的账号按闲置处理。后台额度刷新和其他管理操作不计入使用活动，再次使用后恢复 5 分钟间隔。自动与手动刷新均通过独立进程读取，不等待推理空闲、不占用推理并发槽、不终止推理；同账号刷新串行，凭据变更保持互斥，刷新最短间隔 30 秒、并发上限 2。活动账号也会消费原生通知。受限窗口重置后可更早重读。

`RPC_TIMEOUT`、`QUOTA_TIMEOUT` 和 `RPC_CLOSED` 等临时读取错误在最近一次尝试满 1 分钟后允许后台重试，仍遵守账户启用状态和刷新限流；其他错误沿用正常周期。读取失败保留上次数据，列表提供“刷新失败 · 查看原因”入口，详情显示错误码、采集时间和手动刷新操作。

仅默认 `codex` 桶的已识别明确限制建立账号阻塞；100% 本身不阻塞，其他具名桶没有可靠模型映射时只展示。身份由用户与工作区共同确认，缺少身份时独立处理。快照绑定配置版本，更换凭据使其失效。多个窗口逐项恢复，缺失字段不视为恢复；连续两次相隔至少 30 秒的非耗尽观测可解除阻塞。

到达已知重置时间之后仍未确认恢复时，每五分钟最多允许一个真实业务请求尝试。该请求成功后解除同额度身份的阻塞；其他请求成功不能代替恢复请求。重启保留阻塞依据并重新确认身份，过期缓存不自动恢复。所有新请求经同一调度入口；已有请求不因新额度阻塞被中断。

额度接口需要安装版本和登录方式支持。方法不支持时明确显示“不支持”，未知/读取失败不新增阻塞。Windows/macOS 实机验证分别记录，不将合成测试等同于实机额度读取成功。

## 点数与重置卡

账户列表第二列同时展示上游点数余额、可用重置卡数量；点击“重置卡”打开弹窗，在弹窗内查看到期时间、选择手动或自动模式并确认使用，默认手动。点数按上游十进制文本保存，不换算为 Token；缺失字段显示未知，真实零值保留。重置卡数量采用 availableCount，不以可能被截断的明细数量推算。

读取继续复用原生 account/rateLimits/read；通知只更新实际包含的字段。完整读取缺少字段时清除旧数据，部分通知缺少字段时保留原采集时间，超时数据标记过期。API Key 和第三方提供方不伪造这些权益。

POST /api/accounts/{id}/quota/reset 接收 idempotencyKey（UUID）、context（额度返回的 resetContext）和可选 creditId。手动确认或开启自动模式后调用原生 account/rateLimitResetCredit/consume。服务校验当前原生身份与快照上下文，和登录、凭据变更、额度读取互斥；重置操作使用独立管理连接，可与现有推理并行，不占用推理并发槽、不停止实例。重试沿用原幂等键，浏览器会话只保存幂等键、所选卡片编号与上下文，不保存凭据。返回 reset/alreadyRedeemed/nothingToReset/noCredit；之后重新读取额度，不推算窗口重置结果；只有显式开启自动模式才会自动消耗重置卡。

点数余额、重置卡明细与消费接口以本机原生协议为准；模拟测试不能代替真实账户兑换验收。协议依据见 [官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)。

## 批量维护与迁移

- `POST /api/accounts/batch`：提交 `revision`、`action`（`configure/delete/import`）及最多 32 项。配置使用 `accountIds` 与可选 `enabled/groupIds/maxConcurrency`；未提供字段不修改。导入使用 `items`，每项含 `name`、可选 `source/document/groupIds/maxConcurrency`；批次级分组与并发设置优先。`groupIds` 为非空 UUID 数组，提交时替换全部归属，重复 ID 自动去重；未提交则保留原分组。批量配置和导入不接受单分组字段 `groupId`。
- `POST /api/accounts/export`：以 `accountIds` 显式下载带版本号的 JSON。响应统一 `Cache-Control: no-store`。

批量接口在操作完成后直接返回逐项结果，不保存任务记录，也不提供历史查询、进度查询或停止任务接口。当前数据库结构不包含 `account_tasks`；启动时校验当前结构，不执行旧表迁移或删除，结构不符时保留数据并报错。操作逐项推进 revision，外部修改冲突后跳过剩余项目。启用会复用现有检测，停用等待请求结束，降低并发不打断已有请求；忙碌账号改组或删除返回逐项原因。删除保留历史。客户端断开后已接受的操作继续完成；服务重启不会重放批量操作。

页面在批量配置或删除完成后，以浮动提示汇总成功、失败、跳过数量；存在失败时使用错误提示，仅有跳过时使用信息提示。逐项失败与跳过原因继续保留在页面结果区，供检查并手动关闭。导出完成和操作后账户刷新失败也分别提示。

导入最多 32 项、整批 4 MiB、单项凭据 256 KiB，保留全局 32 账号上限。先解析和校验身份，再新建；重复身份跳过，不覆盖。新账号默认停用，启用失败仍保留导入结果供处理。备份导入时生成新 ID。账户列表提供“导入账户备份”：选择文件或粘贴 JSON 后预览并确认导入；原分组标识不存在时，必须选择目标分组；备份缺少非空 groupIds 时直接拒绝解析。保留原分组时恢复全部分组归属，指定目标分组时统一替换新账户的分组。界面逐项展示成功、失败和跳过原因，导入后手动启用账户。API Key 账户同时恢复基础 URL、上游密钥、传输方式、名称、分组和并发，默认停用，导入后可直接启用，无需补填密钥。本机配置及其他无凭据记录需重新连接；重复导入仅配置记录会新建账户。连接中断时结果可能未知，界面不自动重试，需先刷新列表核对。

包含凭据的导入账户可直接点击启用；首次使用缺少原生安装缓存时，后台自动检测，无需预先手动准备。检测沿用本机连接流程，需保持官方 Codex 桌面运行；失败显示具体错误，账户保持停用，可排查后重试。无凭据账户仍须先登录或导入凭据。

账户备份不恢复旧续聊绑定或原生线程。原客户端保留并完整回传历史时，缺少绑定的请求会正常重新选路，由上游判断是否接受其中的加密历史；成功后建立新绑定，无需手动恢复操作。已有绑定冲突、仅凭响应 ID 续接及待答工具回调仍按各自的归属规则校验，见 [Responses 历史与绑定](RESPONSES.md#保存容量与生命周期)。

列表勾选账户后点击“导出账户备份”，下载包含账户配置的备份包。独立 OAuth 账户详情“登录与凭据 → 凭据管理”另提供“导出凭据”，仅下载可直接通过现有凭据导入表单使用的 JSON，不含账户名称、分组或并发配置。两种下载均需确认；单账户导出在忙碌、排队或登录期间不可用。仅 AT 的凭据仍需手动续期，本机配置和桌面绑定不提供单账户凭据下载。

导出格式为 `{format:"codex-relay-accounts",version:1,items:[...]}`；导入要求非空 `groupIds`，不读取旧单分组字段 `groupId`；每项包含名称、来源、完整所属分组 `groupIds/groupNames`、并发上限、`requiresReconnect` 与可选凭据 `document`。API Key 账户额外包含 `upstream:{baseUrl,apiKey,transport}`，完整备份并恢复上游配置和密钥，`requiresReconnect` 为 `false`；导入时校验地址、密钥和传输方式。独立 OAuth 账号可迁移自身凭据；本机配置、桌面绑定只导出描述，需要重新连接。导出不包含个人桌面凭据、本机配置中的提供方密钥、客户端 API Key、路径或请求历史。凭据和上游密钥不进入批量操作结果、日志和浏览器持久存储；下载的备份文件包含凭据，需妥善保管。

## 当前 clientInfo

账户列表展示运行实例实际使用的客户端名称与版本，详情展示每个实例的 PID、`clientInfo.name/title/version` 和原生初始化返回的 User-Agent。数据取自实例初始化时发送的 clientInfo；不会以最新安装版本替代已有实例的身份。多实例分别列出，正在推理时也可读取；未运行时明确显示无运行实例。此信息只读，不改变客户端身份或发送模型请求。


账户列表的代理摘要会显示自动模式解析出的代理地址和端口；HTTP／HTTPS 使用不同代理时分别列出，两者相同则合并。未配置代理或 NO_PROXY 全部绕过时显示“自动 · 直连”，解析失败明确标注。地址优先来自服务启动环境的 HTTP_PROXY／HTTPS_PROXY／ALL_PROXY；未显式设置时读取 Windows 当前用户或 macOS 系统手动 HTTP/HTTPS 代理。只显示协议、主机和端口，不返回代理用户名、密码、路径或查询参数。

Windows 通过 WinHttpGetIEProxyConfigForCurrentUser 读取当前用户活动连接配置，不修改注册表或全局环境，也不调用外部进程。支持单地址及 `http=...;https=...`；`https=` 代表目标协议，默认仍使用 HTTP CONNECT 代理。列表、位置检测和原生进程共用解析路径；每次读取系统设置，新实例继承新地址，已运行实例保持原配置直到重启。显式 NO_PROXY 保留，`NO_PROXY=*` 不读取系统代理。只配置 PAC 脚本或 SOCKS、以及无法转换的配置会报错，用户可改用指定代理；不执行 PAC/WPAD。Windows 仅开启“自动检测设置”但没有静态代理时按未配置处理。

系统绕过列表转换为 NO_PROXY，支持域名、IP、CIDR、`*.example.com` 和 `192.168.*` 等尾部 IPv4 通配符；本机回环默认绕过。NO_PROXY 无法完整表达 Windows 的 `<local>`（全部无点主机名），目前仅转换 localhost、回环和本机 COMPUTERNAME；如需访问其他内网短名称，请显式设置 NO_PROXY。复杂通配符或按 URL/端口匹配的绕过规则不作猜测，返回配置错误。Windows API 参考：https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpgetieproxyconfigforcurrentuser 。


自动重置设置使用 `GET/POST /api/accounts/{id}/quota/reset/automation`，更新传入 `{enabled, revision}`。默认 `enabled=false`，自动模式下仍可手动使用。服务每 30 秒检查调度，已知卡片在到期前 10 分钟进入使用窗口，使用前重新读取上游库存；只自动选择有明确编号、有效期和可用状态的 Codex 卡片，优先最早到期的一张。无待用卡片时最多每 15 分钟发现一次，未知或失败状态至少间隔 1 分钟。账户停用时暂停自动使用，繁忙账户仍会尝试重置。

幂等键、原卡片与原身份上下文先写入 SQLite，再调用兑换接口。结果不明时保留原请求，重启、切换手动/自动后仍可核验，不新建兑换；账户身份变化时不把未确认请求转移到新身份。手动和自动重置串行执行，同一上游身份的未确认兑换会阻止其他账户另起兑换。确定结果后重新读取真实额度，不自行把用量清零。
