# 分组、并发与运行统计

本阶段参考 [zyycn/codex-proxy-rs](https://github.com/zyycn/codex-proxy-rs) 的分组、并发租约和用量记录设计，研究版本为 `28fa655c26815402652bc29242ac9e09c218300e`。实现适配本项目的 Rust 管理服务与官方原生 app-server 路线；未复制该项目源码。使用单进程有界等待队列，不引入 Redis 或 PostgreSQL。

## 管理界面

- **账户管理**：默认首页，列表展示所属分组、实例运行状态、账户启用开关与并发。日常只使用“启用账户”：开启后自动预热一个可接收推理的实例（不调用模型），健康的常驻实例不因空闲回收，额外实例空闲 120 秒回收；后台每 30 秒在账户空闲时补齐失效实例，服务重启后恢复已启用且分组未暂停的原生账户实例，API Key 账户直接连接上游、无需实例；关闭后拒绝新请求，等待当前任务完成后停止实例，保留配置与登录凭据。操作区提供测试对话、展开详情、账户设置和删除入口，手动启动、停止和重启统一位于详情“高级能力 → 实例维护”，手动启停不改变账户启用状态；启用账户被手动停止后，后台会恢复其常驻实例，需要持续停止时应关闭账户启用开关。详情“接入与调度”只保留同一个启用账户开关，以及所属分组、并发设置；已配置路由的账户也可设置1–256个并行请求。列表点击所属分组可勾选多个分组并保存，执行或排队期间不可修改归属。
- **分组管理**：创建、编辑、暂停分组、删除空分组并运行调度检查。每个账户可同时属于多个分组，至少保留一个；默认分组不可删除，有账户归属的分组不能删除。账户归属与并发设置统一在“账户管理”及账户详情的“接入与调度”管理。
- **等待队列**：位于“请求监控”的“等待队列”标签。查看真实入队顺序、操作、账户 / 分组、已等待时间与距离超时的时间；每 2 秒刷新，支持分组筛选与每页 50 条分页。可逐项取消尚未执行的请求。
- **调度检查**：组内轮询选择启用且有剩余容量的账户，启动该账户的原生实例并调用 `account/read`。结果只证明派发和原生连接正常，不证明模型推理可用。实例可在账户页停止。
- **用量统计与请求记录**：默认显示浏览器本地时区的今天，可筛选开始、结束日期，并按分组、账户、请求类型和状态过滤；模型用量概览、24 段趋势、账户／密钥／模型排行和运行质量见下方[用量统计页面](#用量统计页面)。明细默认每页 20 条，可切换 50 或 100 条。两个页面均每 30 秒自动更新，也可点击刷新图标。日期范围通过 `/api/statistics?from=<毫秒>&to=<毫秒>` 查询，包含两端边界；`hours` 查询与日期参数互斥。
- **系统设置**：连接与调度在同一面板分区管理总并发、队列参数、账户亲和时间和请求记录保留天数，各区独立保存；访问安全承载后台密码及公网访问；环境与诊断承载安装准备、诊断和桌面调试。停止中转站位于侧栏底部版本信息旁的电源图标，所有页面均可打开确认弹窗；手机端先展开导航菜单。
- 页面右上角通过图标切换浅色和深色模式。

账户主开关使用 `POST /api/accounts/{id}/activation`，请求体为 `{ "revision": 1, "enabled": false }`。首次开启时检查原生认证并读取路由，恢复已有配置时直接启用。关闭保留路由并将账户策略 enabled 设为 false；固定到账户的排队请求被拒绝，按分组排队的请求可由其他启用账户承接。当前任务完成后记录 `management / stop_disabled` 并停止实例；等待期间重新开启会取消这次自动停止。`/route` 用于检查并设置推理路由，`/policy` 用于保存分组、启用状态和并发策略；账户页面通过 `/policy` 保存调度设置。

## 并发规则

账户通过任一已启用的所属分组接收请求；暂停某个分组只阻止该分组的请求，不影响其他所属分组。账户并发、健康状态和上游额度在所有分组间共享，全局自动容量只计算每个账户一次。请求及用量归属实际调用的分组，不会在所有所属分组中重复计数。账户策略与快照统一使用非空数组 `groupIds`，不再接受或返回单分组字段 `groupId`。API Key 和请求记录仍用 `groupId` 表示实际授权或调用的单个分组。

服务总并发默认使用自动模式，按所有未删除账户配置的并发上限求和；新账户默认 5，因此两个默认账户的总并发为 10。添加、删除账户或修改账户并发后立即更新，自动汇总不受手动模式 256 的上限限制。停用账户保留配置容量，但仍无法接收客户端请求。在“系统设置 → 连接与调度”可切换手动模式，指定 1–256 的固定总上限；切回自动后仍记住上次的手动值。切换模式不修改各账户的并发设置。没有账户时显示总容量 0，保留一个管理操作槽位以便完成初始设置。账户容量允许 1–256；调用方 Key 配额和执行容量检查及占用在同一临界区完成。分组仅用于路由授权和启停，不再接受或返回分组 maxConcurrency 字段。管理 API 的受限操作遇到任一级额度满时进入等待队列。这里限制的是执行中的请求数量，不是每分钟请求数，也不是启动的账户进程数量。

默认最多等待 64 个请求、最长等待 30 秒，可在“系统设置 → 连接与调度”调整为 1–4096 个请求、1–300 秒。队列容量为整个管理服务共享的等待请求数，不包含已执行请求。队列满返回 `429 QUEUE_FULL` 和 `Retry-After: 1`；到期仍未获得额度返回 `504 QUEUE_TIMEOUT`。超时仅针对获得额度前的等待，不是原生操作执行超时。

队列按入队顺序选出最早可执行的请求；暂时受账户容量或调用方配额阻塞的项可被跳过，让其他有容量的分组继续执行。同样可执行的新请求不插队。按组推理请求在实际出队时重新综合评分选择账户，管理调度检查保留轮询，等待时不占账户或执行额度。额度释放、配置更新和排队请求退出都会唤醒等待者，容量检查与出队占额保持原子性。

暂停账户或分组返回 `503 ROUTE_DISABLED`；组内没有启用账户返回 `503 NO_ELIGIBLE_ACCOUNT`。调度跳过暂停或已满的账户，不在原生操作失败后自动重试其他账户。

降低并发上限不会中断既有请求，已有数量超过新上限时需等待自然释放。暂停会拒绝新请求，并使受影响的等待请求以 `ROUTE_DISABLED` 结束；不打断已执行请求。停止实例和取消登录不受并发额度、队列或暂停状态限制；它们仍会记录结果。账户存在执行或排队中的操作时不能迁组。请求完成、出错或任务被取消均释放额度；被取消的排队任务从队列移除，不再派发原生操作。

降低队列长度不逐出已有等待请求，后续入队需等待数量降到新上限以下。修改等待超时仅影响之后入队的请求；已有请求保留入队时的截止时间。等待中的 HTTP 请求保持连接，客户端超时应留出排队与执行的总时间。当前没有持久化任务重放，也没有针对 HTTP 断连额外实现取消协议；队列取消保证针对服务端等待任务被取消或丢弃，等待超时仍始终生效。诊断维持原有同一时间仅运行一项的额外约束。

管理员可通过界面或 `POST /api/requests/{id}/cancel` 主动取消排队请求。取消与出队派发共用同一临界区：取消先发生时，原等待 HTTP 请求收到 `409 REQUEST_CANCELLED`，其原生操作不会执行；出队先发生时，取消接口返回 `409 REQUEST_NOT_QUEUED`，不终止已运行操作。已取消请求再次取消会返回成功与 `alreadyCancelled: true`。未知请求返回 404。取消不删除统计记录，历史中保留 `cancelled / REQUEST_CANCELLED`。

正常 Ctrl+C 退出时先停止接收新的受限请求，并结束所有排队等待（原请求返回 `503 SERVICE_SHUTDOWN`，历史标为取消）；已执行推理请求收到取消令牌，等待中断与进程清理；其他已执行操作继续完成，然后关闭本服务拥有的账户实例。写入失败时也会释放等待者，不让退出卡在队列超时上。直接结束进程、崩溃或断电仍按下一次启动的中断恢复处理。

配置更新携带 `revision`，旧版本返回 `409 CONFIG_CONFLICT`，避免静默覆盖其他操作。一个运行目录只允许一个管理服务持有锁。

## 统计口径与持久化

“用量统计”的“用量排行”通过分段按钮切换账户、API 密钥和模型，默认按密钥聚合，选择写入 URL 的 `usageBy`（`account` / `key` / `model`）并在刷新后保留。表格显示当前筛选范围各实体的请求次数、请求占比、失败次数、输入／输出／总 Token、用量占比、平均首响、平均模型首响、平均总耗时和缓存命中率。点击“请求次数”或“总 Token”列标题的排序图标，可切换对应的降序排列；默认按用量，排序保存在 URL 的 `usageSort`（`tokens` / `requests`）。同值按 ID 排列，未知用量排在最后；切换排序不重新请求统计数据。占比分母为当前聚合维度全部匹配记录的请求次数或已知 Token 总量。

`GET /api/statistics` 返回 `accountUsage`、`keyUsage`、`modelUsage`，每项包含 `id`、`name`、`requestCount`、`failedRequests`、`inputTokens`、`outputTokens`、`totalTokens`、`usageKnownRequests`、`averageFirstResponseMs`、`averageModelFirstResponseMs`、`averageTotalMs`、`cachedInputTokens`、`cacheKnownInputTokens`、`cacheKnownRequests`、`cacheHitRate`；汇总全部匹配记录，不受明细分页影响。账户与密钥排行包含管理和检查等全部匹配记录；模型排行只包含推理记录，按请求模型 ID 聚合，未记录模型时返回空字符串 ID、null 名称，界面显示“未知模型”。失败次数仅统计 `failed` 状态，响应耗时和缓存指标只使用推理请求中的已知样本。

总 Token 只累加输入、输出都已知的记录，缓存已包含在输入中，不重复累加；全部未知时为 null，明确的 0 保持为 0，输入或输出的单项已知合计不一定能相加得到完整样本的总 Token。请求次数包含未知用量、失败、拒绝等匹配记录；未分配账户的请求仍计入对应密钥次数。仅列出筛选范围内有记录的实体，账户和密钥按 ID 合并，名称使用范围内最近的非空快照；删除实体后其历史排行仍保留，清空请求历史时一起清除。

统计与账户用量查询使用独立只读连接和一致性快照，不持有调度锁；管理接口通过限流的后台读取任务执行，避免同步 SQLite 查询阻塞异步网络线程。

数据位于 `data/accounts/operations/operations.sqlite3`，使用 WAL；父级账户目录沿用当前 Windows 用户与 SYSTEM 的访问限制。配置持久保存；请求记录默认保留 30 天，可在“设置 → 连接与调度 → 请求记录”设置为 1–365 天。持久化配置必须包含该字段。保存设置时立即清理；服务启动最多清理 1,000 条，随后后台每分钟清理一批。每批最多 1,000 条，满批时隔 100 毫秒继续，批次之间释放调度锁；请求接收不执行清理。按请求开始时间清理超期记录；执行中和排队中的请求不会被清理。对应统计与失败诊断内容随记录一起删除，延长时长不能恢复已清理的数据。续聊账户绑定的保留策略独立于本设置。

`POST /api/settings/retention` 接收 `{ "revision": <当前版本>, "retentionDays": <天数> }`，返回更新后的运行设置；保存时长和立即清理在同一事务中完成，旧版本返回 `409 CONFIG_CONFLICT`。重启将执行或排队中的未完成记录标为 `interrupted / SERVICE_RESTARTED`，再按保存时长清理，并发与等待计数重新从零开始，不自动重新派发。项目尚未正式发布，存储结构按当前实现调整，不要求保留旧开发数据格式。

记录包括时间、操作类型、账户与分组的名称快照、状态、耗时、错误代码。失败的 Responses 请求还保存原请求参数与响应内容；原请求保留消息结构，省略提示词、指令、工具调用内容和附件，隐藏凭据字段。HTTP 保存响应 JSON 与状态码，SSE / WebSocket 保存失败终态事件；内容有大小、条目数和单字符串上限，截断时明确标记。成功请求不保存这些内容。历史记录沿用当时归组，迁组和重命名不重写历史。删除分组不删除其历史记录，全量查询仍可查看；API 可用原分组 ID 筛选。

成功率为成功数 /（成功数 + 失败数）；不包含拒绝、等待超时、取消、中断、排队或进行中。平均执行耗时仅计算成功与失败的完成操作，不含排队或原生实例的存活时间。平均排队耗时包含已结束等待的请求和无需排队的零等待请求，不包含尚在排队或历史等待时间未知的请求。

同一个请求从 `queued` 到 `running` 再到终态只保留一条记录，次数不重复累计。等待超时单列为 `timed_out`，队列满计入 `rejected`；明细分别显示执行耗时和排队耗时。全局当前排队是实时值，不受历史筛选条件影响。账户操作、诊断、原生调度检查与模型推理分别归类。读取统计和修改配置本身不计为请求。

目前统计与限并发覆盖管理 API 启动 / 登录 / 导入凭据、管理页面触发的诊断，以及账户 / 分组原生检查和客户端 Responses 请求、原生 WebSocket 会话。停止与取消登录记录但不占额度。通过 CLI 直接运行的探针、桌面调试连接、桌面自身流量不在此范围。登录操作的耗时仅到原生登录入口返回，不包括用户随后在浏览器完成认证的时间。

`/v1/native` 会话在匹配到本机配置或已验证的 OAuth 路由后进入调度模块，租约覆盖整个连接、工具等待与进程回收。记录增加 Key ID、原生 thread/turn ID 与输入/输出 Token；原生会话累计 usage 在结束时结算一次。汇总 inputTokens/outputTokens 累计已知值，usageKnownRequests 表示有用量的请求数；无数据为 null。模型用量显示缓存输入 Token 与缓存命中率，不显示费用。缓存命中率为 SUM(cachedInputTokens) / SUM(inputTokens)，分母只包含返回缓存用量的请求；按 Token 加权，不取每请求命中率的平均。缓存数据缺失时为未知，不按零计；明确返回 0 才表示未命中，输入总量为 0 时命中率未知。请求详情和 `/v1/usage` 同样提供缓存字段。未通过鉴权、参数或模型路由匹配的请求尚未进入调度统计。密钥管理见 [调用方接入](CLIENT-ACCESS.md)。

结算写入失败会标记存储不健康并拒绝后续受限请求，需检查磁盘并重启服务。停止账户和取消登录保留应急路径：即使统计不可写仍执行清理；清理成功但结果无法记录时返回 `ok: true, recorded: false, warning: ...`，界面显示警告。该路径不允许新建原生操作绕过统计故障。

## 调用方并发

每枚 API Key 可设置 0–256 的独立并发上限，0 表示仅沿用服务总容量和实例容量约束。Key 额度与服务 / 实例执行容量在同一锁内检查和占用；等待者按所有额度都可满足的顺序出队。并发占用持续到本轮执行、必要清理和结算完成；HTTP 文本续聊保留的空闲进程不占额度，等待请求不占执行额度；不按时间窗口限制请求次数。

Key 配额调整会唤醒队列；降额保留执行中的请求。暂停或撤销 Key 后等待请求立即重新鉴权并被拒绝，原生会话每 10 秒复核权限，失效后结束会话。设置入口及语义见 [调用方接入](CLIENT-ACCESS.md)。

本机入口与独立 HTTP / HTTPS 客户端监听共用这些计数、队列与统计；同一 Key 切换接入地址不会获得额外并发额度。网络配置见 [网络接入](NETWORK-ACCESS.md)。

## 管理 API

管理接口首次启动默认免登录、允许外部访问，已有访问设置保持不变，始终检查 Host / Origin。“系统设置 → 访问安全”可分别设置密码登录和公网访问，开启公网不要求密码。密码模式下管理 API 需要会话 Cookie；修改已有访问设置还需当前密码。开启 `--require-admin-token` 后还需 `Authorization: Bearer <本次启动管理令牌>`。对外调用者始终使用独立 API Key。

| 方法与路径 | 用途 |
| --- | --- |
| GET `/api/session` | 登录方式、公网开关及当前会话状态 |
| POST `/api/session/login` | 使用 password 登录，设置 HttpOnly 会话 Cookie |
| POST `/api/session/logout` | 注销当前后台会话 |
| GET / POST `/api/settings/access` | passwordEnabled、allowPublicAccess；可选 password、currentPassword。保存即生效并注销其他后台会话 |
| GET `/api/operations` | 配置版本、分组、账户策略、实时并发和 nativeAffinityTtlHours |
| GET `/api/statistics` | 概览、趋势、accountUsage / keyUsage / modelUsage 和分页明细；支持 from/to 或 hours，以及 groupId、accountId、kind、status、keyId、model、errorCode、keyName、accountName、groupName、page、pageSize |
| DELETE `/api/requests` | 清空全部请求记录；JSON body 为 `{"confirmed":true}`，返回删除条数；有执行中或排队请求时返回 409 |
| GET `/api/requests/{id}/content` | 管理端按需读取失败请求的原请求与响应内容；返回 `id`、`request`、`response`，未采集的内容为 null；不通过统计列表或客户端用量接口返回 |
| GET `/api/queue` | 当前等待列表；支持 groupId、accountId、page；position 是全局队列位置 |
| POST `/api/requests/{id}/cancel` | 仅取消等待中的请求，已执行请求返回 409 |

“用量统计”展示请求活动与模型用量概览，可带当前筛选跳转至“请求监控”的请求记录。请求表格直接显示密钥、账户与分组、模型与推理强度、UA 标识、输入/输出及缓存 Token、首响、模型首响、总耗时、状态和请求时间，详情通过弹窗查看。`model` 保存请求模型，`responseModel` 单独保存上游报告的实际模型；模型列仅在两者不同时，在第二行用转向箭头显示实际模型。推理强度单独一列。实际模型来自直通响应的 `response.model` 或原生 `model/rerouted.toModel`，不以请求值或路由配置推测；原生接口未报告、旧记录未保存时为 null，详情显示“未记录”。`reasoningEffort` 保存请求的 `reasoning.effort`；新请求未指定时为 `default`，界面显示“默认”，表示由原生配置或模型决定，并不推测具体等级。`userAgent` 记录调用方的 User-Agent，最多保留 512 个字符，超长内容用省略号标记；未提供时保持未知。密钥名称在准入时保存快照，后续密钥改名或删除不改写历史名称。

`firstResponseMs`（界面显示为“首响”）从请求进入调度统计起，到记录首个有效输出（文本增量、推理摘要增量或工具调用输出），包含排队时间；`firstDeltaMs`（界面显示为“模型首响”）从排队结束、开始执行起，到记录首个有效输出（文本增量、推理摘要增量或工具调用输出），不含排队；`totalMs` 从进入统计起到服务端结算，包含排队、执行和清理，不代表客户端完整接收用时。模型首响包含服务端开始执行后的准备时间，不等同于客户端收到首个字节的时间。未完成的请求没有总耗时，未记录有效输出的请求没有首响或模型首响，均保持 null；明确的 0 保留为 0。原生函数调用、自定义工具调用、工具搜索及服务端工具输出在通过校验并生成对外事件时记录首响；只有创建事件或不含可见增量的推理元数据不会触发计时，后续输出不覆盖首次时间。原生工具仅报告完整调用时，此时间表示完整调用可供转发的时刻，不推测参数的首字节时间。

在“请求监控”的请求记录标题旁点击“清空所有记录”，确认后会删除全部时间、全部分组的记录，不受当前筛选条件限制。请求图表、Token 用量统计随之清空，账户、API Key 和调度设置保留。清空使用事务，与请求准入共用锁；有执行中或排队请求时需要先结束或取消，新请求在清空后继续正常记录。

## 网关改造：请求与能力

参考版本固定为 `zyycn/codex-proxy-rs@76291f448cdf1d1da2027da32b7c949deb998c7a`，独立实现适合本项目的生命周期和能力管理；保留原生模型传输与 SQLite。

所有客户端 HTTP 入口生成服务端 `X-Request-ID`，包括认证和参数错误。推理请求沿用该 ID 记录排队、原生执行、响应保存和结算。客户端提供的同名头不作为内部主键。

模型结果与客户端响应结果分开：保存失败会记为失败，但保留模型完成状态与已知 Token。原生执行错误优先于后续清理错误，清理错误另列。请求详情增加 Key、模型、原生 thread/turn、失败阶段、首个文本增量耗时和交付记录。`handed_off` 仅表示交给响应通道，不保证客户端收到了最后一个字节。

`GET /api/statistics` 新增 `keyId`、`model`、`errorCode` 精确筛选；历史未记录字段为 null。`GET /v1/usage` 使用调用方 Key，只返回自身最近 24 小时的请求、Token、当前执行/排队和并发上限，不暴露其他 Key 或消息正文。

连续三次实例启动/RPC 故障进入 30 秒冷却，到期后调度器仅允许一个请求尝试恢复，不受配置的账户并发值影响；成功后清零。取消、错误参数、本地排队满不增加失败计数。

Codex/ChatGPT 登录账户收到结构化 `rateLimitExceeded` 或已知原生错误变体内的 HTTP 429 后，立即在请求结算时暂停该账户的新调度。短期冷却依次为 30、60、120、240、300 秒，最高 5 分钟；同一冷却窗口内多个在途请求的 429 合并计算，不按并发请求数量连续翻倍。冷却到期、旧请求排空后仅允许一个恢复请求，成功后恢复正常并发；取消或失败会释放恢复名额，再次限流则延长冷却。旧请求的迟到成功不会提前解除冷却，账户路由变化后旧结果不会污染新路由。

上述短期冷却只适用于原生 ChatGPT 登录身份，API Key 直连账户和原生 API Key 配置均不参与。账户按本地账户 ID 与路由版本隔离，不因共用 OpenAI 地址而连带暂停其他独立账户。当前原生 TurnError 没有可靠的 Retry-After 字段，因此使用有上限的退避，不从错误文本猜测时间。当前失败请求不自动重放或换账户重试；后续未绑定请求可以调度到其他可用账户。原生长会话遇到此类限流会发送终态并结束会话，及时结算冷却；额度耗尽仍按独立的额度通知及恢复机制处理。短期冷却保存在进程内，重启后重新判定。

`GET /api/capabilities` 显示模型、原生提供方能力、验收结果与健康状态。读取路由时通过原生 RPC 刷新目录；缓存按安装 SHA-256 和提供方指纹隔离。失败保留最后成功目录并标为过期，重启后必须重新刷新才可使用新增能力。目录缺项不禁止原有非默认文本模型。能力缓存新鲜期一小时。

能力和历史数据不是账号凭据的替代物。

## 账户代理

代理设置下方提供默认关闭的“时区与搜索位置”，可跟随出口或自定义，并同步对话时间与搜索位置。设置行为和接口见 [账号时区与搜索位置](ACCOUNT-LOCATION.md)。

在“账户管理 → 账户详情 → 接入与调度”中设置“账户代理”。每个账户单独保存；账户列表显示当前代理模式并可直接进入设置。系统设置不再提供全局代理。

- 自动（默认）：优先使用中转站启动环境的代理变量；未指定时读取 Windows 当前用户或 macOS 系统手动 HTTP/HTTPS 代理。系统设置变更后，新检测和新实例读取新设置；已运行实例需重启。
- 直连：清除该账户子进程的代理变量，直接联网。
- 指定代理：填写 HTTP/HTTPS 地址，例如 `http://127.0.0.1:7897`，不含账号密码、路径和查询参数。本机回环地址绕过代理。

代理用于所属账户的登录、凭据刷新、模型请求、额度查询、能力检查和后台模型目录刷新。已有账户的本机检测在 `POST /api/local-connection/inspect` 中携带 `accountId` 并使用此账户代理；尚未关联账户的本机检测和导入准备使用自动模式。桌面共享调试连接不提供该配置。

保存立即持久化配置，并暂停此账户的新任务调度；其他账户不受影响。保存后立即停止旧执行器并自动重启原本运行的实例，会中断此账户当前的请求和交互登录；停止的账户保持停止。排队请求保留现有超时。连续保存采用最新配置；停用、停止或删除账户会阻止待执行的重启。

页面区分“已生效、切换中、切换失败”。切换失败保留配置并暂停此账户调度，可点击“重试切换”或修改配置后重新保存。保存只校验地址格式，不发起模型请求，也不代表代理可达性验证。

管理接口 `POST /api/accounts/{id}/proxy` 接收 `{ "revision": 1, "config": { "mode": "custom", "url": "http://127.0.0.1:7897" } }`，返回更新后的 operations 快照。mode 为 `auto`、`direct` 或 `custom`；revision 使用编辑开始时的快照版本。每个账户返回 `proxy` 和 `proxyStatus`（`applied`、`switching`、`failed`）。重试通过同一接口重新提交已保存配置。不存在全局代理接口或旧配置迁移。

## 同一账户多对话并发

账户详情“接入与调度 → 账户并发上限”可设置1–256；例如账户4、服务总并发8、Key上限0时，同一账户最多同时执行4个请求。多个Key或同一Key的不同对话共用账户容量，Key自己的上限仍单独生效。已有设置保持，新账户默认5；启用、恢复启用、刷新路由和本机接入不会再把已保存的并发重置成1。超额请求沿原有界队列等待，默认30秒超时；提高并发不保证上游配额或速率限制消失。

普通 Responses HTTP/SSE 和 Responses WebSocket 在账户内共享兼容进程，不同请求拥有独立工作目录、原生线程及取消记录；空闲线程按同一 Key、账户、参数和完整历史匹配，并重新校验当前分组对账户与模型的授权；同一 Key 改分组后授权仍有效时，可以继续使用存活线程和工具回调。原生 `/v1/native` 长会话和旧文本入口仍使用独占执行槽位；原生显式压缩复用原生认证，通过 HTTP 在内存中完成。单个客户端取消只中断自己的 turn；手动停止账户取消该账户全部在途请求并关闭全部缓存进程；禁用账户仍等待已有请求自然结束。登录、凭据变更与原生维护在账户内独占执行，降低并发不取消已接受的任务。

验证入口：`node scripts/cargo-with-memory.mjs test --locked --test account_concurrency`及`profiles::pool::tests`验证额度、等待、维护互斥和请求注册；`pnpm --filter @codex-relay/console test account-concurrency.spec.ts`验证表单。端口冲突时可设置`BRIDGE_TEST_WEB_PORT`启动独立测试服务。`scripts/test_account_concurrency.py --binary <已构建程序>`使用独立测试目录、合成凭据与localhost模型，验证安装的原生app-server实际并发、续聊隔离、单请求断开及账户整体停止，不消费真实模型额度。该检查不等同真实上游账户的并发配额或生产负载验证。

当前数据库结构为版本 7；空库由 `operations/schema.sql` 初始化，已有数据库由 `operations/schema.rs` 校验。结构或版本不符时返回 `DATABASE_SCHEMA` 或 `DATABASE_VERSION` 并保留原数据；调度说明为可空字段，未参与智能调度的记录显示“未知”。`requests.request_content`、`response_content` 默认保存失败诊断，启用请求原文调试后也保存限长原文，随请求记录保留与清理；续聊恢复只使用账户绑定指纹，不读取调试原文。采集与清理规则见 [请求原文调试](DEVELOPMENT-CHECKS.md#请求原文调试)。

## 多账户智能调度

Responses、原生会话首次分配和旧文本入口自动采用综合调度。先检查分组、模型授权、账户启停、能力策略、并发、额度阻塞及冷却，再在当前最佳能力等级中评分；目录未知仍可参与。管理调度检查保留轮询。已开始的请求保持账户不变，不自动换账户重放。

总分为负载 45%、额度余量 25%、近期稳定性 20%、首字速度 10%，分项均为 0–1。额度取有效 Codex 窗口的最小剩余比例，未知或超过五分钟按 0.5；稳定性初值 0.9、EWMA 系数 0.2，取消、参数错误、排队与本地存储错误不会降低分数。速度按相同模型、推理强度和请求类型比较，以候选首字耗时中位数 `M` 和账户耗时 `T` 计算 `M / (M + T)`；少于五个有效样本或十分钟未更新按 0.5。耗时不含排队，不使用总执行时长。

与最高分相差不超过 0.01 时按轮询游标打散。每组每 20 次没有命中粘性的实际分配，选择同能力等级中最久未分配的可用账户探索；候选检查、排队和管理操作不推进计数，不发送额外模型探测请求。出队时重新评分，选择和容量占用保持原子性，保留原队列顺序与截止时间。

响应链、历史条目和加密历史的强绑定优先。原生账户软亲和优先使用当前逻辑线程 ID，缺失时使用逻辑会话 ID，再回退会话请求头、`prompt_cache_key` 和稳定指令、工具及首条 user 消息摘要。软亲和键由调用方 Key、模型和对话身份摘要组成，分组不参与；包含工具的请求也可使用。换组不主动清除亲和绑定，每次选路仍按当前授权范围检查原账户是否可用。身份来源及优先级见 [Responses 会话隔离](RESPONSES.md#原生传输与兼容范围)。API Key 直连不建立或续期原生亲和绑定。

绑定在获得请求租约时原子建立，默认有效期为准入时刻之后 24 小时，可在「系统设置 → 连接与调度 → 账户亲和」调整为 1–720 个整数小时；仅入队、查询、鉴权失败或准入记录写入失败均不续期。临时分流成功准入时保留并续期原账户绑定，原账户恢复可用后继续优先选择；模型响应完成不再写回绑定，执行失败也不回滚准入时的绑定。原账户通过现有健康、权限、能力和并发检查且有空位时优先选择，不增加亲和等待，不因轻微评分差距换账户；不可用时立即按原有规则调度，所有账户满载时沿用原队列。硬绑定决定实际账户，不能被软亲和覆盖。

子代理和分支首次准入时可以继承明确父线程的已有首选账户，但各自建立独立绑定。父绑定不存在或不可立即执行时正常调度，不替父线程创建绑定、不续期父绑定；子线程已有有效绑定后不再随父线程改配。绑定最多保留 4,096 条，优先清理过期条目，再按最近成功准入顺序淘汰。账户删除、路由凭据或代理变化使相关绑定失效，Key 撤销或删除时清除对应绑定；调整 Key 或账户的所属分组不主动清除绑定，下一次请求会重新校验原账户是否仍属于可用范围，不合格时重新选路并建立绑定。账户临时暂停不直接删除绑定。新建绑定拥有独立版本，旧请求完成或延迟清理不能恢复、删除新版本。

亲和设置通过 `/api/settings/native-affinity` 更新 `nativeAffinityTtlHours`，范围为 1–720 个整数小时，沿用全局配置 revision。保存后持久化，重启保留设置；已有绑定的到期时间不立即改写，新绑定和下一次成功准入续期使用新时长。

此 TTL 只控制本地账户选路，不代表原生线程或上游 Token 缓存可以保留 24 小时。线程复用仍须校验完整历史和工具回调；实际缓存命中以已报告用量为准，未知缓存用量不能按零处理。

原生缓存优化开启时，每个共享 Responses 进程默认保留 64 个存活线程、128 MiB 上下文数据预算。可用 `BRIDGE_NATIVE_MAX_THREADS`（1–256）和 `BRIDGE_NATIVE_CONTEXT_BUDGET_MIB`（32–1024 MiB）启动配置调整，重启生效；不新增管理台配置字段。资源不足时优先清理同一逻辑身份已被后续成功对话取代的空闲线程，再按最近成功使用顺序淘汰。正常续聊优先保留目标线程，未确认原生线程关闭前不返还容量。工具等待、独立搜索及进程空闲回收另有各自边界，详见 [Responses 资源回收](RESPONSES.md#原生传输与兼容范围)。

启动时设置 `BRIDGE_NATIVE_CACHE_REUSE=0` 可回退：恢复原有纯文本完整摘要、120 秒有效期、0.08 评分差距及歧义判断，并恢复工具交还后中断原生 turn。默认开启；关闭时账户亲和时间设置仍保存，但不用于旧版纯文本亲和逻辑。亲和绑定仅保存在服务内存中，重启后清空；持久化的是亲和时间设置。

软粘性缓存与性能统计分别最多 4096 项，使用内存 LRU；粘性只保存摘要，不增加聊天正文存储。重启清空，账户删除、路由或代理变化会使相关记录失效；分组调整不主动清除软亲和绑定，后续准入仍校验授权范围。请求详情中的“账户调度”和“调度说明”展示算法版本、选择方式、分项评分、候选数量及粘性判断；未参与智能调度的记录显示“未知”。隔离账户验收脚本为 `python scripts/test_smart_scheduling.py`，仅连接本地模拟上游。


请求记录默认按每页 20 条从服务端分页读取，可切换 50／100 条；分页栏始终显示当前页、总页数和总记录数。修改筛选或每页条数后回到第一页，记录减少导致页码越界时回到最后一个有效页。统计接口的 `pageSize` 只接受 20、50、100，省略时为 20；汇总和排行仍统计筛选范围内的全部记录。


## 请求参数兼容说明

请求详情的“参数兼容说明”来自记录中的 `parameterHandling`，每项包含参数路径、处理方式和原因，不保存参数值。“已忽略”表示选项没有按调用方设置生效，“适配”表示存在转换和语义限制；条目数不是错误数，也不是工具调用次数。历史中重复出现的 custom 工具声明可分别记录在不同 `input[…]` 路径下。

排查时结合请求状态和错误码：工具格式或解析失败需关注 custom 的 grammar 限制；工具执行顺序需关注 `parallel_tool_calls`；缓存效果应查看实际缓存输入 Token，不能仅凭 `prompt_cache_key` 的本地适配或忽略说明判定缓存是否命中。具体解释见[如何理解参数兼容说明](RESPONSES.md#如何理解参数兼容说明)。

## 子代理请求标记

请求记录返回可空的 `subagentKind`，只根据客户端明确声明识别，不从 UA、模型名或输入文本猜测。支持请求头 `x-codex-turn-metadata` JSON 中的 `subagent_kind` 和 `x-openai-subagent`，以及正文/`client_metadata` 中的 turn metadata（`x-codex-turn-metadata`、`turn_metadata`、`turnMetadata`）和 `client_metadata.x-openai-subagent`。逐请求/逐 WebSocket 帧的正文标记优先于连接请求头，同一来源优先采用 turn metadata；无标记时为空。标签去除首尾空白，拒绝空值、超过 128 字节或包含控制字符的值；解析 turn metadata 最多读取 16 KiB。该标记仅用于观测，不参与鉴权或调度。

列表仅在有明确子代理类型的模型推理记录中，于“推理强度”旁显示机器人图标，悬停及辅助技术可读取类型。普通请求和历史无标记记录没有图标；不会补猜历史记录。HTTP、WebSocket、API Key 直连均在调度入队或拒绝时保存标记。


API 密钥支持 `fastMode`（默认 `false`）。创建和编辑窗口可开启“强制快速模式”，列表在开启的密钥名称旁显示闪电。开启后，新的 Responses 请求及 compact 请求统一使用顶层 `service_tier: "priority"`，覆盖客户端原值；关闭时保留客户端设置。支持原生转译、API Key 直连、HTTP 和 WebSocket，每个 WebSocket 请求重新读取密钥策略，已接收请求保留当时设置。导出/导入保留此配置，备份中的 fastMode 为必填字段，缺少时拒绝导入。请求记录分别保存接收请求时生效的 `serviceTier` 和上游明确返回的 `responseServiceTier`。API Key 直连从非流式响应或流式终态响应读取实际 `service_tier`，HTTP、SSE 和 WebSocket 使用同一记录逻辑；不会用请求参数填充实际等级。列表在模型名称右侧用填充闪电表示上游确认快速模式，用警示色描边闪电表示请求快速模式后被降级；已请求快速模式但上游未返回等级时显示灰色描边闪电，列表不显示“未确认”文字。详情分别显示请求与实际服务模式，缺少实际等级时注明未确认。原生 Codex 协议当前不明确回传实际等级，保留未知状态。后续修改密钥设置不影响已保存记录。实际等级字段的建表定义与校验使用当前数据库结构；缺少该字段的旧开发数据目录会保留数据并拒绝打开，不自动迁移或重建。


## 本地调度负载验证

`node scripts/cargo-with-memory.mjs test -p codex-relay --test account_concurrency hundred_requests_with_large_history_and_concurrent_statistics -- --ignored --nocapture` 在隔离临时数据库中生成 10 万条历史，配置 10 个账户各 10 并发，同时运行 100 个请求的调度/结算与统计查询，输出接收延迟 P95/P99。测试不调用真实模型，不验证上游限流、原生进程内存或真实首响；结果不能代替完整账户链路压测。

请求记录的筛选入口位于标题右侧，选择密钥名称、账户、分组、模型或请求状态后，输入内容并按 Enter 或点击搜索图标应用；多个条件可叠加，也可逐项移除。账户和分组输入完整候选名称或完整 UUID 时按 ID 精确筛选，其余文本按名称关键词搜索；请求状态必须匹配候选项，无效输入会在输入框旁提示。密钥名称、账户名称和分组名称通过 `keyName`、`accountName`、`groupName` 按记录保存的名称快照进行区分大小写的字面子串匹配，支持已改名或已删除的历史记录，分页和汇总使用同一筛选范围。

`python scripts/test_account_concurrency.py --binary target/debug/codex-relay.exe --check-standby` 使用隔离的本机配置和本地模拟上游，验证预热不发起模型请求、空闲 125 秒后首个请求复用预热进程、并发会话隔离，以及停用后不自动补建实例。需要已准备的原生 app-server。

`python scripts/test_account_concurrency.py --binary target/debug/codex-relay.exe --capacity` 额外创建 10 个隔离账户，各允许 10 并发；让本地模拟上游同时挂起 100 个请求，断言每账户均有 10 个在途请求，再释放并核对全部完成。该测试使用真实原生进程，但不调用真实模型，也不代表真实 ChatGPT 服务端限流或长上下文容量。检查范围、修复及验证边界见 [请求链路检查记录](PERFORMANCE-AUDIT.md)。

请求准备日志 `request_preflight` 现在区分 `session_match`、`account_preparation_wait`、`slot_selection`、`native_worker` 和 `account_and_route`，便于分别衡量锁外历史匹配、账户锁等待、实例选择/启动和并行认证配置的耗时。已认证实例复用与当前绑定及凭据摘要匹配的有效认证结果；凭据变更或接近到期会重新读取，并发刷新合并。客户端密钥权限仍逐请求校验。

原生账户亲和与逻辑身份验收可运行 `python scripts/test_account_concurrency.py --binary target/debug/codex-relay.exe --affinity-only`，覆盖首轮完成前建立绑定、繁忙时临时分流、恢复后回到原账户、子线程继承与独立绑定，以及 WebSocket 逐帧身份隔离。`scripts/test_native_affinity.py` 是该入口调用的辅助模块，不单独运行。使用隔离账户、安装版 app-server 和本地合成上游，不发送真实模型请求；默认 Rust 与浏览器测试不能代替此验收。

## 用量统计页面

用量概览优先展示模型请求数、总 Token、输入／输出 Token 和缓存命中率，并显示完整用量已知的请求数与未知数。总 Token 只累加同时具有输入和输出用量的模型请求，缓存输入已经包含在输入中，不额外相加；未知用量与明确的零保持区分。管理与检查请求仍保留在全部记录和运行质量统计中。

支持今天、近 7 天和近 30 天快捷日期，保留其他筛选条件。分组、账户与状态等条件通过日期旁的“筛选”按钮展开，已选条件数持续显示。请求卡片显示当前筛选范围的模型请求成功、失败数量，不含管理检查、取消或排队状态；模型请求总数包含执行中、排队、取消等状态。模型请求、总 Token、缓存命中率在顶部各自直接显示小趋势，未来时段不绘制为零；下方同时展示输入、输出和缓存输入曲线，可用悬停、点击、方向键或展开时段表格查看数据；趋势、模型用量排行和概览覆盖当前筛选范围的全部记录，不受请求分页影响。模型排行按请求中的模型 ID 聚合，未记录模型的请求归入“未知模型”。账户和 API Key 排行继续统计筛选范围内的全部请求。点击排行名称可带着日期和其他筛选条件进入对应请求记录。排行同时显示失败请求次数、平均首响、平均模型首响、平均总耗时和缓存命中率；响应耗时仅汇总模型请求中的已知样本，缓存按已知输入加权，不受明细分页影响。

缓存命中率与缓存用量已知请求数直接显示在顶部概览，不单独展示下方缓存用量卡片。每个趋势时段返回 `cachedInputTokens`、`cacheKnownInputTokens`、`cacheKnownRequests`、`cacheHitRate`，遵循相同口径；未知样本使曲线断开，明确的 0 保持为 0，输入分母为 0 时命中率仍为未知。缓存命中率与未命中输入仅基于缓存用量已知的样本。命中率 = 这些请求的缓存输入 Token 之和 ÷ 输入 Token 之和，先汇总再计算，不对单请求百分比取平均；输入分母已包含缓存读取，输出不参与分母。命中率不表示费用节省比例。

账户调度卡片显示全局实时并发占用、并发上限、空闲并发、排队数和上限模式，不受历史日期和账户筛选影响。空闲并发仅表示全局容量，不保证所选分组具有可调度账户。运行质量与排队位于页面下方，可展开查看。完成成功率为成功数除以成功与失败数之和，不含拒绝、取消、中断与等待超时。平均首响与平均模型首响使用同一批已知有效输出时间的模型请求样本，前者包含排队，后者从开始执行计时、不含排队，但仍可能包含连接和执行准备；未知耗时不计为零；平均总耗时仅使用已结算模型请求，包含排队、执行和清理。实时排队和并发保持全局口径。

### 请求连接信息

请求表在“连接 / 客户端”列集中展示端点、上游协议、接入协议和 User-Agent，详情分别列出这些字段。WS 表示 WebSocket，SSE 表示 HTTP 事件流，HTTP 表示普通 HTTP 响应。API Key 直连的上游协议取实际连接结果，包括 WS 回退到 HTTP 的情况；原生 app-server 执行显示“原生”，不推断其内部网络协议。未记录的协议显示“未知”。

当前 requests 表增加 endpoint、client_transport、upstream_transport 字段。依照开发期数据库规则，缺少这些字段的数据目录会被拒绝打开，不自动迁移、清空或重建。
